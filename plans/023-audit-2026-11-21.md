# 023 — Audit of 2026-11-21

## Status

- **Priority**: P1
- **Effort**: M
- **Risk**: MEDIUM. The fixes touch the daemon's delivery loop, history
  storage, the quit confirmation and the test gates; each landed with a
  test that failed before it.
- **Depends on**: 001–007
- **Category**: quality
- **Planned at**: 2026-11-21, from the owner ("35 auditors then fix")
- **State**: IN REVIEW (2026-11-21). The 22 confirmed findings are fixed
  in PRs #23 to #27. Cross-family review (GPT-6.1 Sol) is outstanding:
  that model was not available to the session that made the fixes. The
  64 low findings below were not verified and stay open.

## Problem

M1 and M2 are done and M3 has begun, built by many pull requests. The
owner asked for a broad audit of `main` and fixes for what it found.

## Method

- **Audit.** 35 read-only auditors read `main` at `e303513`. Each had one
  area of the code or one concern: the dry-run contract, `exec.rs`, `Root`,
  the server's protocol and its concurrency, history, the samplers, the
  CLI, MCP, the tray, the root helper, the interface, the gates, the
  units and the docs. They ran no build, no test and no git write.
- **Verification.** A separate verifier read the code for each finding
  rated medium or higher and tried to refute it. It defaulted to "not
  real" when the code did not confirm the finding.
- **Results.** 22 findings survived verification and none was refuted.
  Six were lowered to low on verification. Findings first rated low were
  not verified. They are listed under "Open: low findings, not verified".
- **Fixes.** Five Opus 5.5 implementers worked in parallel, one per area,
  each in its own worktree. Every fix has a test that failed before it.
  Signalling processes is security-sensitive, so the quit-confirmation
  fix (A7) is its own pull request with its test written first.
- **Review.** A fresh-context reviewer of the same model family read every
  pull request. That is a stopgap, not the cross-family review the
  account's routing requires. Its findings are under "Review follow-ups".

## Found while fixing

- **`main`'s full run had been red since #20.** In `tests/test-bench.sh`,
  the idle and live cases measured the debug build against the release
  build's 15 MiB budget (15.2 MiB on CI). The cloned-root case also still
  expected 37 user processes after `tests/fixtures/procs.tsv` grew to 47.
  Pull requests run only the affected tests, so none of them caught it.
  Fixed in #27 with an 18 MiB debug ceiling, as the tray case already
  had; CI's `bench` step still gates the release budget. The debug
  apps-at-400 case then measured 2.0 % against the 1.5 % release CPU
  budget ([run 44887716678](https://github.com/t1nk333r/mirqab/actions/runs/44887716678)),
  so #27 gives it a 3 % debug ceiling, best of two runs; it passed in
  [run 44889620747](https://github.com/t1nk333r/mirqab/actions/runs/44889620747).
- **A lib test is flaky on `main`.**
  `samplers::apps::actions::tests::the_compositor_probe_skips_dead_sockets_and_fails_closed`
  (`crates/mirqab-core/src/samplers/apps/actions.rs:1123`) failed 2 of 20
  runs at `e303513`, with "nobody listens" and a pid in the result. It is
  not fixed here.

## Review follow-ups

- **#24.** Hiding the sheet freed Quit while a plan was still out. A
  second Quit after the window came back stacked two dialogs. A
  generation counter now drops the stale reply, and the widget test
  covers the case. The CLI socket tests also gained a drop guard for
  their scratch directory.
- **#25.**
  - The dGPU pace is now limited to a card whose `power/control` is
    `auto`.
  - `node --env-file`, `--title` and `--inspect-port`, and `ruby -C` and
    `-E`, now skip their separate value when the job is named.
  - The pushed commit `4789651` held a synthetic home path in test data.
    It is listed in `tools/secrets-allow.txt` and the case is now
    relative.
- **#26.** These went back to its implementer:
  - only the default history directory is made private; a directory the
    user named is left as it is;
  - corruption found by a query now starts recovery;
  - a file moved aside never overwrites an earlier one, and recovery
    backs off;
  - the process `prime` age limit;
  - the 360-point bound.
- **Left as a follow-up.** `apps` has the same "sleep under the sampler
  lock" pattern as the process `get` fixed in #26
  (`crates/mirqab-core/src/samplers/apps/mod.rs:620-650`).

## Rejected

- **Fixing the low findings in the same pass.** They were not verified,
  and some are design questions rather than defects. One example is L31,
  units in field names, which would mean renaming stream fields and their
  golden files. Each needs a verifier's read before anyone changes code.
- **Merging on same-family review.** The routing policy names a different
  model family as the independent reviewer. With none available, review
  stays outstanding rather than self-certified, and the owner decides
  whether to merge.

## Unverified

- **The suspended check on Hyprland.** #24 drops a Graph's live
  subscription when its window reports xdg_toplevel `suspended`. Does
  Hyprland send `suspended` for a minimised window, or one on another
  workspace? Broadway cannot show it.
- **Disk temperatures at 2–5 s.** Live readers at 2–5 s, such as bar
  items and the System page, still read disk temperatures. Plan 002's
  follow-up of reading disks every 10 s is still open.
