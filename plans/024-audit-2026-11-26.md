## Problem

Plan 023's fixes (#29 to #40) were reviewed by one model family only.
The owner asked for a second broad audit of `main` and fixes for what it
found.

## Method

- **Audit.** 30 read-only auditors read `main` at `686575e` in three
  passes of ten. The ten slices were the same in each pass: core
  infrastructure, the server and protocol, history and config, the
  system sampler, the apps sampler, ports with the desktop, tray and
  bar, the CLI, MCP, the interface with `mirqab-view`, and the helper,
  units, tests, tools and docs. Pass 1 looked for correctness, pass 2
  for security, privacy and the CLAUDE.md contracts, and pass 3 for
  regressions in #29 to #40, the resource rules, tests that cannot fail
  and docs out of step. Each pass was given the findings of the passes
  before it so it would not repeat them. Plan 023's fixed, rejected and
  owner items were excluded.
- **Verification.** A separate verifier read the code for every finding,
  medium and low alike, and tried to refute it, defaulting to "not real".
  All 19 findings rated medium or higher held; 12 of them were lowered to
  low. Of the 37 lows, all were real, and three were judged not worth
  fixing.
- **Fixes.** Eight Opus 5.5 implementers worked in parallel, one per
  area, each in its own worktree. The quit confirmation's shown names
  (L18) and quit's exit codes are signalling work, so that pull request
  (#47) is separate and its tests were committed before the fix.
- **Review.** A fresh-context reviewer of the same family read each
  branch, ran its tests, and asked for changes until it approved an
  exact head. That is a stopgap, not the cross-family review the routing
  requires.

## Not fixed

- **L7.** The daemon refuses an unknown `--range` word with BadRequest,
  and the CLI exits 1. `tests/test-cli.sh` pins that exit on purpose, and
  `CLI_EXITS` defines 1 as "refused or failed". Moving the check into the
  CLI to exit 64 would change a tested contract for little gain.
- **L25.** `test-cli.sh` does not name `history.rs` or `config.rs` in its
  covers globs, but `test-rust.sh` covers `crates/mirqab-core/**` and its
  affected mode runs `cargo test -p mirqab` too, whose
  `a_fixture_daemon_keeps_history_beside_its_socket` checks the same
  placement. A history regression is caught on the pull request.
- **L33.** `supported` in a -32022 refusal lists every revision the
  server speaks, legacy ones included, because those are served through
  `initialize` (plan 005). The list is right; only the `_meta` path
  refuses them.

## Review findings

- **#44 (L1).** The first fix returned a timeout at once and reaped a
  child stuck in uninterruptible sleep on a detached thread. The reviewer
  showed that with a broken NVIDIA driver this starts one more stuck
  `nvidia-smi` and one more thread every minute, without a bound. The
  fix now starts no program again while its killed child is still dying,
  so at most one is held. Approved at the second review.
- **#45 (C11).** The first fix checked the host's file with a plain
  `metadata` walk while the owners lock was held, and the path is chosen
  by a process in another mount namespace, so a stalled FUSE mount on it
  could hang the lock. The check now crosses local mounts only and runs
  outside the lock. Approved at the second review.
- The other six were approved at the first review.
- **Merges.** #43 and #44 conflicted with branches merged before them.
  For #43, a resolution git had recorded during a trial merge first
  dropped #42's two history tests; they were restored, and #42's
  open-time history-off journal line was moved into `strings.rs` as L13
  does for the others. For #44, the `bar` one-shot get now both sends
  the stream params (C18, C19) and treats an unreadable frame as an
  error (L32). A fresh reviewer compared each merge file by file with
  the approved head and approved it.

## Partly fixed and trade-offs

- **C10.** A FIFO, a device or a socket among the `.desktop` files is
  refused before any real open, and an entry over 256 KiB is skipped. A
  symlink into a stalled FUSE or NFS mount can still block: the path
  walk to the link's target looks names up before a descriptor can be
  pinned. The doc comment says so.
- **C5 and C7.** The executable is opened with `O_PATH` and read only
  from a local mount. On a hard NFS mount the `O_PATH` open through the
  `exe` link can still revalidate under the sampler lock.
- **C11.** Overlay is not counted as a local filesystem, so a process in
  a container, or on a host whose `/usr` is overlay or composefs, shows
  no `arch`.
- **C12.** A cut comm is replaced by argv[0] only when argv[0] has no
  whitespace, so a program run from a directory with a space in its path
  keeps the cut comm.
- **C19.** With history off and no `gpus` reader in the last 90 s, the
  thermal word of `temp`, the tray and MCP counts no NVIDIA card.
- **C8.** The live check now runs twice for 4 s and fails only if both
  runs are over. That makes the flake much less likely without removing
  it; the budget is still a strict 1 %.
